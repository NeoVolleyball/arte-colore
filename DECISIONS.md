# Decisions log (Phase 1 redesign, branch `magic-ui-phase1`)

## Plan (written before coding)

1. Keep Vite + React 18 + TypeScript and the prerender (SSR) build; add Tailwind v4 via `@tailwindcss/vite`.
2. The new single-page site replaces the home page (`index.html`) with its own entry (`src/site/main.tsx`) and its own CSS, so Tailwind's reset never touches the legacy `/prodotti/` and `/negozio/` pages.
3. Add the `@/` alias, `motion`, `cn()` (clsx + tailwind-merge) and a hand-written `components.json` with the `@magicui` registry.
4. Design tokens live in one file, `src/site/styles.css` (CSS variables + Tailwind `@theme`): stone/off-white base, terracotta accent, dark band variant, Fraunces + DM Sans self-hosted.
5. Primitives (`Section`, `Container`, `Heading`, `Button`) in `src/components/site/primitives.tsx`; every section uses them.
6. Business facts are placeholders in `src/data/site.ts`; content arrays in `src/data/projects.ts`, `wallpapers.ts`, `offers.ts` (offers only read through `offersService.ts`).
7. Sections in order: Header, Hero, SPC, Lavori fatti, Decorativi, Sconti, Zone servite, Contatti, Footer; below-the-fold sections are code-split with `React.lazy` in the client while the prerender still renders all content.
8. The existing Three.js hero (`HeroVisual` + `src/three/heroScene.ts`) is reused unchanged as the hero visual on desktop only (it already lazy-loads, skips mobile/Save-Data/no-WebGL and goes static under reduced motion).
9. New SVG logo (mark + wordmark, colour + mono), favicon, apple-touch-icon and a 1200×630 share image rendered from SVG with Playwright.
10. Verify with lint, tests, build and Playwright screenshots at 360/768/1280 px; finish with README, PLACEHOLDERS.md and this log.

## Decisions

- Tailwind v4 with `@tailwindcss/vite` (Vite 5.4 is supported); its CSS is imported only by the new home entry, so the legacy pages keep their own `global.css` untouched.
- `index.html` now loads `src/site/main.tsx`; `src/main.tsx` + `src/pages/registry.tsx` serve only the legacy `/prodotti/` and `/negozio/` pages, which still build and prerender but are no longer linked from the new home. The old `HomePage.tsx` and its sections are kept on disk unused, for reference; delete them once the client approves the redesign.
- `npx shadcn init` and `npx shadcn add @magicui/<name>` cannot reach `ui.shadcn.com` / `magicui.design` from this sandbox (egress policy 403). `components.json` was written by hand with the `@magicui` registry exactly as requested. Components were installed with the same shadcn CLI from the identical official registry JSON published in Magic UI's GitHub repo (`raw.githubusercontent.com/magicuidesign/magicui/main/apps/www/public/r/<name>.json`). A local stub answered the CLI's `colors/stone.json` request. On a normal connection, `npx shadcn@latest add @magicui/<name>` works as-is.
- Magic UI items install to `src/components/ui/` (the registry's own target). Small edits are marked `arte-colore:` in the files: `magic-card` drops `next-themes` (light-only site), `bento-grid` replaces the unavailable shadcn `button` and `@radix-ui/react-icons` with a plain link and an inline SVG, and `number-ticker` gains a `locale` prop for Italian price formatting.
- Prerender now awaits `getActiveOffers()` and embeds the result as JSON (`#app-data`), so the client hydrates from exactly the same offers (no mismatch, no layout shift) and then re-checks expiry in the browser.
- Palette: off-white `#faf7f2`, stone `#f1ebe3`, ink `#1f1a17`, terracotta accent `#a3432a`, dark band `#221c18`. Every text pair was measured and passes AA, most pass AAA. Ochre and sage are decorative only.
- Fonts: Fraunces (display) and DM Sans (body) as self-hosted variable fonts from `@fontsource-variable` (`font-display: swap`, unicode-range subsets), so no Google Fonts request is made.
- Motion: one curve (`--ease-out`, exposed as `ease-brand`) and three durations. A global `prefers-reduced-motion` rule neutralises CSS animations, and `MotionConfig reducedMotion="user"` does the same for `motion` animations.
- Plan item 7 changed: below-the-fold sections are NOT wrapped in `React.lazy`, because React 18's `renderToString` would prerender only Suspense fallbacks and remove the content from the HTML (bad for SEO and no-JS). Instead, heavy parts are code-split and mounted only in the browser: particles, the Three.js scene and its still. Images use `loading="lazy"`. `content-visibility: auto` was tried and dropped: it made anchor jumps land imprecisely and saved little on a page this size.
- Hero: the existing Three.js scene (`HeroVisual`, paint tin + colour chips) is kept unchanged as the right-hand visual on ≥1024px only. It is lazy-imported, skipped on Save-Data and static under reduced motion. Phones get three small material tiles instead, so they never download the 200 kB still or three.js. The obsolete mobile preload of `hero-still-720.webp` was removed from the home page.
- Hero headline: `word-rotate` starts on "spazi", runs through pavimenti/pareti once and rests on "spazi". This avoids endlessly moving text (WCAG 2.2.2), and it stays static under reduced motion. Screen readers get the full sentence once, via an `sr-only` copy.
- Portfolio hover uses `glare-hover` rather than `lens`: `lens` adds its own focusable region inside each card and duplicates the image. `lens` and `blur-fade` (whose server-rendered content starts invisible) were installed and then removed as unused.
- Lightbox is a native `<dialog>` with `showModal()`, which gives focus trapping and Esc to close. Arrow keys and buttons change photos, and clicking the backdrop closes it.
- Placeholder photos are procedural illustrations (`scripts/make-placeholders.py`), never presented as real jobs. Each card shows a "Foto di esempio" badge driven by `example: true`, and example offers are titled "[ESEMPIO]".
- Offer prices: `number-ticker` counts down from the old price to the new one when in view. The server-rendered text is already the final price, and it is static under reduced motion. The countdown renders dashes until mounted and uses fixed-width tabular digits, so there is no hydration mismatch or layout shift. A date-only `endsAt` means 23:59:59 Europe/Rome (DST-safe), and expired offers disappear live.
- Offers with `newPrice >= oldPrice` are hidden too (an invalid discount), and the Italian comment in `offers.ts` says so.
- "Zone servite": San Marco and Belle Arti are shown as areas, as the brief asks. NOTE: the previous site used "San Marco" as a paint-brand retailer network and "belle arti" as a fine-art product category. Confirm with the client what these names should mean here (also in PLACEHOLDERS.md).
- QR code is generated at build time from `site.url`/`VITE_SITE_URL` by a tiny Vite virtual module (`virtual:site-qr`, using `qrcode` as a dev dependency), so it adds no runtime library.
- The mobile call/WhatsApp bar is always visible below 768px. The footer has extra bottom padding there so nothing is hidden under the bar.
- Logo: a mark of three fanned tiles (sage, ochre, terracotta) with a paint stroke on the front tile, plus the "arte-colore" wordmark in Fraunces 560 with a terracotta hyphen. The wordmark is converted to outlines (fontTools), so the SVG needs no font. Files: `src/assets/logo.svg` (colour), `src/assets/logo-mono.svg` (`currentColor`, the stroke is a cut-out), and a copy at `public/logo.svg` for JSON-LD.
- `public/favicon.svg` (mark on an off-white tile) replaces the old favicon, which also changes the legacy pages' favicon. `public/apple-touch-icon.png` (180 px) and `public/og-image.jpg` (1200×630) were rendered from the SVG/HTML with Playwright.
- The hero's italic accent word uses a synthesized italic of Fraunces, so no extra italic font file is downloaded above the fold.
- Hero backdrop: on a GPU-less desktop, the Three.js scene and the particles canvas *together* dropped to ~3 fps (Lighthouse desktop TBT 30 s), though each alone ran at 60 fps. So capable desktops get the 3D scene and no particles. Desktops that skip 3D get the still image plus particles, and phones get neither. `HeroVisual.canUse3D()` (now exported) also skips software WebGL renderers (SwiftShader/llvmpipe) and ≤2-core CPUs. This is the only change to the legacy 3D code.
- Fonts: the two Latin variable WOFF2 files are preloaded on the home page (hash-aware, injected at build), which brought mobile CLS from 0.039 to 0.
- SEO: the home page head (title, description, canonical, OG, Twitter, JSON-LD) is generated from `site.ts` by the existing Vite SEO plugin. `robots.txt` and `sitemap.xml` (home only) are always emitted. Lighthouse SEO flags canonical/robots/link URLs only while they still contain `[PLACEHOLDER]` brackets.
- Hero still/scene frame gets a soft radial mask plus `mix-blend-multiply`, so the rendered still (opaque background) melts into the hero instead of showing a rectangle.
- Results on the final build (sandbox Chromium, served by `vite preview`, real `VITE_SITE_URL`): Lighthouse mobile 97 performance / 100 accessibility / 100 best practices / 92 SEO; desktop 100/100/100/92. The only SEO miss is the "Vedi sulla mappa" link, whose placeholder `https://[…]` URL is not crawlable; it passes once the real link is set. CLS is 0 and TBT ≤ 40 ms. No horizontal scroll at 360/768/1280 px, and no console errors.
- Verified with Playwright: mobile menu (focus in, Esc closes and returns focus, closes on navigation), anchor scroll offset, skip link, lightbox (Enter, arrows, Esc, focus return), offers section and link hidden when all offers are expired, no particles under reduced motion.
- GitHub Pages: merged the default branch's Pages work (deploy workflow, `VITE_BASE`, `withBase()` in `src/content/paths.ts`) into this branch. The new site's image paths (hero tiles, SPC, portfolio, wallpapers, offers) and the font preloads now go through the same base path. Checked with a `/arte-colore/` build: no broken images or requests, and all interaction checks pass.
